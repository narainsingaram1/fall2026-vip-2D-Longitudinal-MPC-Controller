This is a separate, runnable research experiment. The original simulator remains
available at the repository root. The experiment replaces its STOP/GO objectives
within a new controller rather than editing the old implementation.

**Branch:** `experiment/elliptical-potential-2d`.

## 2. Execution plan and why it follows this order

1. Inspect the baseline: its controller predicts only route position and speed,
   uses BFGS for separate STOP and GO costs, and delegates crossing permission
   to FIFO or the direction-based concurrent scheduler.
2. Define a common world frame and fixed lane centers, so cars at the same route
   distance on different roads are not incorrectly treated as colocated.
3. Define vehicle footprint geometry before selecting the potential. Otherwise
   an attractive-looking ellipse can have no defensible relationship to a crash.
4. Implement three penalties using the same geometric distance and normalization.
5. Derive the full acceleration gradient through the prediction model, then
   verify it against finite differences before interpreting driving results.
6. Run closed-loop MPC with the same initial conditions for every configuration.
7. Check executed motion independently of the optimizer, including motion between
   samples. Export failures, nonconvergence and incomplete runs alongside successes.
8. Select a working candidate using separation, completion and comfort together.

## 3. Dynamics: what changes from the original model

For constant acceleration during one sampling interval:

\[
x_{k+1}=x_k+v_{x,k}\Delta t+\tfrac12a_{x,k}\Delta t^2,
\quad v_{x,k+1}=v_{x,k}+a_{x,k}\Delta t,
\]
\[
y_{k+1}=y_k+v_{y,k}\Delta t+\tfrac12a_{y,k}\Delta t^2,
\quad v_{y,k+1}=v_{y,k}+a_{y,k}\Delta t.
\]

The state is `z=[x,y,vx,vy]`. `step(z, acceleration)` returns four updated
components; `predict(z, acceleration_sequence)` returns four trajectory arrays,
including the initial state. `step` accepts arbitrary planar acceleration.

The controller deliberately restricts acceleration to each vehicle's fixed lane
heading: `a_xy = u * heading`. West/east vehicles control x acceleration;
south/north vehicles control y acceleration. This is planar collision-aware
**speed control**, not a steering, bicycle-model or lane-changing controller.
It has four state components per car and one control component per car.
All four states are assumed known exactly. "Obstacle detection" here means
geometric proximity evaluation from those states; no camera, lidar or learned
perception pipeline is implemented.

| Vehicle | Heading | Lane center | Initial route coordinates: staggered / simultaneous / offset [m] | Initial speeds [m/s] |
|---|---|---|---|---|
| 1, west → east | (1,0) | y=-1.75 | -24 / -28 / -25 | 7 / 7 / 6 |
| 2, east → west | (-1,0) | y=+1.75 | -30 / -28 / -32 | 7.5 / 7 / 8 |
| 3, south → north | (0,1) | x=+1.75 | -36 / -28 / -29 | 8 / 7 / 7.5 |
| 4, north → south | (0,-1) | x=-1.75 | -42 / -28 / -38 | 8 / 7 / 7 |

`world_position = lane_offset + route_coordinate * heading`.
Vehicles are 4.5 m long and 1.8 m wide. Heading and body orientation stay fixed.
The run ends after all center route coordinates reach +12 m, or at 24 s.
Exit times have 0.2 s sampling resolution. Cars continue moving and participating
in collision checks after their individual exit until the whole run ends.

**Scope change:** this experiment studies geometric crossing coordination without
mandatory full stops. It does not preserve all-way-stop compliance. Its timings
must not be advertised as direct improvements over the original FIFO system.

## 4. Elliptical geometry: distance, buffer and actual collision

For pair `(i,j)`, let `r = position_i - position_j`. Let `h_i` and `h_j`
be the world-axis half-length/half-width vectors of the two rectangular bodies.
Define expanded pair exclusion half-extents:

\[
b=h_i+h_j+(m,m),\qquad m=0.5\text{ m},
\]
\[
A=\sqrt2\,b_x,\quad B=\sqrt2\,b_y,\quad
Q=\operatorname{diag}(A^{-2},B^{-2}),\quad q=r^TQr.
\]

The unexpanded rectangle `|r_x|<=h_ix+h_jx` and
`|r_y|<=h_iy+h_jy` is the exact relative-center overlap region for these
axis-aligned bodies. The ellipse is an **outer approximation**: its boundary
passes through the corners of the expanded rectangle. For any point inside
that rectangle, `q <= 1/2+1/2 = 1`. Therefore `q>=1` excludes actual body overlap
with the modeled margin. The converse is false: `q<1` can still have no overlap.

The factor sqrt(2) matters. Using just the rectangle half-extents as ellipse
semi-axes would inscribe an ellipse and miss the rectangle's corners.

- `q>1`: outside the conservative pair buffer.
- `q=1`: boundary of that buffer.
- `q<1`: buffer intrusion; inspect the rectangle check to determine body overlap.
- `q=0`: coincident centers. A radial potential's position gradient is zero
  exactly here, which is one reason a penalty cannot certify collision avoidance.

For parallel headings, `(A,B)=(7.071,3.253)` m. For perpendicular headings,
the combined footprint is square, giving `A=B=5.162` m: this particular ellipse
is a circle. The general formulation remains elliptical; forcing anisotropy
into a square combined footprint would need a separate justification.

Both cars are represented. This is not a point-car test or the sum of two
unrelated scalar route positions. The margin expands the pair exclusion by
0.5 m per axis, not each car by 0.5 m.

### Independent check over the entire executed interval

During an interval, relative position is `r(t)=r0+dv*t+0.5*da*t²`.
Thus `q(t)` is quartic. `swept_pair` evaluates its endpoints and all real roots
of its cubic derivative inside the interval to find the minimum.

For physical overlap, it finds roots where either component of relative
position reaches a rectangle boundary, partitions the interval at those events,
and checks endpoints and interval midpoints. Each component has constant sign
relative to its boundaries inside each partition. This detects overlap between
simulation samples. Floating-point polynomial roots still have numerical
tolerances; this is not a formal arithmetic proof.

## 5. Candidate objective functions and selection rationale

All candidates are normalized to `phi(1)=1`. Equal weights therefore match their
boundary cost; their gradients, penetration costs and tails intentionally differ.
This is a transparent comparison, not a claim that equal weights are equally tuned.

| Candidate | Formula | Benefit | Limitation |
|---|---|---|---|
| Gaussian | `exp(1-q)` | Smooth, cheap, rapidly decaying tail | Finite center cost `e`; a low weight may tolerate overlap |
| Regularized reciprocal | `1.05/(q+0.05)` | Stronger near-center penalty; center cost 21 | Long tail can brake cars that are already well separated; epsilon affects tuning |
| Squared softplus | `[log(1+exp(beta*(1-q)))/log(2)]²` | Smooth, focuses cost near and inside boundary; strong intrusion cost | Nonconvex in relative position; finite weight still cannot enforce separation |

Use `beta=5`. Softplus is implemented with `logaddexp`, avoiding numerical
overflow. Its center cost is approximately 52.2 and its cost at q=2 is about
0.000094. Reciprocal remains 0.512 at q=2; Gaussian remains 0.368 there.

**Working candidate: squared softplus.** Its short tail avoids persistent
repulsion between already-separated cars while its smooth, substantial
intrusion penalty gives the speed planner a useful warning near the boundary.
The measured results determine whether that rationale holds for these runs;
see `RESULTS.md` and `FINDINGS.md`. It is not established as universally optimal.
These are proposed simulation objectives, not formulas presented as a certified
vehicle-safety method from the background reference.

For `z=beta*(1-q)`, `L=log(1+exp(z))`, and sigmoid `sigma(z)`:

\[
\frac{d\phi}{dq}=
-\frac{2\beta L\sigma(z)}{(\log2)^2},\qquad
\nabla_r\phi=2\phi'(q)Qr.
\]

## 6. Full MPC cost, parameters and comfort reasoning

At every simulation step optimize **all four cars'** next N=20 acceleration
commands together. The horizon is 4 seconds and DT=0.2 s:

\[
J(U)=\sum_{n=1}^{N}\sum_{i=1}^{4}
\left[w_v(v_{i,n}-8)^2+w_a u_{i,n-1}^2+
w_j\left(\frac{u_{i,n-1}-u_{i,n-2}}{\Delta t}\right)^2\right]
+w_o\sum_{n=1}^{N}\sum_{i<j}\phi(q_{ij,n}).
\]

For the first jerk term use the last **applied** acceleration. At simulation
start that value is zero. Reference speed is 8 m/s for every car.

Default weights are `wv=1, wa=0.15, wj=0.10, wo=100`.
These are simulation tuning values, not experimentally established passenger
comfort thresholds or physical risk prices. The heterogeneous terms have
different units; the weights supply the required scaling. All terms use the
same fixed sampling period; inserting a common DT factor would rescale the
objective without changing its minimizer, but changing DT requires retuning.

Hard constraints are `-3 <= u <= 2` m/s² and predicted speed in `[0,10]` m/s.
Jerk and separation are **soft costs**, not hard constraints. There is no
collision safety filter, hidden braking fallback or priority scheduler.

Why squares? Minimizing signed acceleration rewards maximum braking.
Minimizing acceleration squared discourages both braking and acceleration.
The jerk term discourages sudden command changes, including the first command.
Minimizing these alone produces no useful progress: the desired-speed term
balances comfort with motion, while the potential penalizes geometric conflicts.
Control effort is an acceleration-squared integral, not a battery/fuel model.

## 7. Iterative update, step size, direction and stopping condition

Use optimization iteration `ell`, distinct from physical time index `k`:

\[
s^{(\ell)}=-\nabla_U J(U^{(\ell)}),\quad
U^{(\ell+1)}=\Pi_\mathcal C
\left(U^{(\ell)}+\alpha_\ell s^{(\ell)}\right).
\]

`alpha` starts at 0.15 for each update and halves until projected Armijo
sufficient decrease holds. At most 22 backtracking attempts are allowed.
At most 60 accepted/attempted outer iterations are used in the comparison suite.
Only the first acceleration from the solution is applied. Shift the remaining
sequence forward to warm-start the next solve and repeat using the measured state.

For fixed-heading dynamics, predicted speed and position depend linearly on U.
The matrices are `V[n,m]=DT` for m<=n and
`P[n,m]=(n-m+0.5)*DT²` for m<=n, zero otherwise, using zero-based rows.
The code propagates the speed, jerk and position-potential gradients analytically.

The feasible set is the intersection of an acceleration box and linear speed
halfspaces. The Euclidean projection uses Dykstra's algorithm, with up to 100
cycles and explicit residual checks. If the acceleration-box projection already
satisfies speed constraints, it is also the projection onto the intersection.
An inaccurate warm-start projection falls back to zero acceleration, feasible
from any currently feasible speed. Inaccurate trial projections are rejected.

The stationarity diagnostic is `||Pi(U-alpha*g)-U||/alpha`, tolerance 1e-4.
At a constrained optimum the raw gradient need not be zero. A saturated
acceleration can have nonzero gradient because improvement lies outside the
feasible set. Also, J need not approach zero: competing goals may remain.

Every solve saves its cost trace, constraint violation, projected residual,
iteration count and status. An iteration limit is reported as such, not called
convergence. Descent during one solve does not imply monotonic closed-loop cost:
the state and planning horizon change between solves. Nonconvexity prevents
any global-optimality claim.

## 8. Controlled experiment matrix

| Configuration | Changed quantity | Purpose |
|---|---|---|
| no_obstacle | wo=0 | Same-controller ablation: show what geometric term changes |
| gaussian | phi=Gaussian | Compare finite short-tail repulsion |
| reciprocal | phi=reciprocal | Compare strong center/long-tail repulsion |
| softplus | Default | Working candidate |
| softplus_low_safety | wo=10 | Less emphasis on separation |
| softplus_high_safety | wo=500 | More emphasis on separation |
| softplus_comfort | wa=0.60, wj=0.40 | Increase both comfort terms by factor four |
| softplus_no_jerk | wj=0 | Isolate the jerk term |

Every configuration runs staggered, simultaneous and offset arrivals.
This is a small deterministic study, not a statistical traffic benchmark.
The comfort variant changes two coefficients together as a comfort package;
it does not isolate acceleration weighting from jerk weighting.

Metrics include completed vehicles, clearance, continuous-in-step minimum q,
rectangle-overlap pair-steps, buffer-violation steps, acceleration and jerk RMS,
peak acceleration and jerk, acceleration-squared integral, speed extrema,
solver status counts and computation time. RMS is pooled over cars and applied
time steps. Because runs can have different duration, interpret RMS with duration
and completion. No throughput estimate from four cars is presented as capacity.

## 10. Interpretation boundaries and next engineering decision

A smooth penalty can trade collision risk for tracking performance at finite
weight. A successful sample is evidence about that sample, not a guarantee.
Perfectly symmetric arrivals can trap a symmetric controller in coordinated
braking instead of producing a crossing order. Increasing repulsion can make
that problem worse. Do not tune away a failure by hiding its scenario.

The practical next implementation should combine this comfort objective with
explicit right-of-way to break ties, hard predicted separation constraints, and
a verified emergency policy that considers braking feasibility. Test uncertainty,
infeasible starting states, turning vehicles, repeated traffic and sensing delay
before making any deployment claim. Those additions are outside this isolated
potential-comparison experiment and are not implied to be implemented here.

Koren and Borenstein document local minima and oscillation problems in potential
field navigation. Their robot experiments provide background for skepticism,
not validation of this controller or its numerical coefficients:
[Potential Field Methods and Their Inherent Limitations for Mobile Robot Navigation](https://www.cs.cmu.edu/~motionplanning/papers/sbp_papers/integrated1/borenstein_potential_field_limitations.pdf).

## 11. What is actually being used

- Python and NumPy: state propagation, geometry, analytic gradients, projection.
- Optional Numba: compiles the same Dykstra projection loop for faster stress
  runs. This machine used Numba 0.63.1. Without Numba the NumPy implementation
  runs unchanged but symmetric stress cases can take several minutes each.
  Install the optional acceleration with `python3 -m pip install numba==0.63.1`
  if compatible with your Python/NumPy versions; it is not required for correctness.
- SciPy: independent constrained projection oracle in tests, not control solves.
- Matplotlib: static scientific figures and animation frames.
- Pillow: GIF encoding.
- JSON, CSV and compressed NumPy archives: reproducible results, not a live service.
- No learned model, LLM controller, external vehicle simulator, map service,
  GPU requirement is used in the driving loop.
